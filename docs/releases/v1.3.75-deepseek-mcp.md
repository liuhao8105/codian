# v1.3.75-deepseek-mcp

## Overview

This release adds a **read-only MCP bridge** for the DeepSeek provider, enabling DeepSeek to discover and call MCP tools from configured servers. Also added **DSML protocol filtering** to prevent internal protocol tokens from leaking into the chat UI. Codex provider is unchanged.

## What's New

### Read-Only MCP Bridge

DeepSeek can now use MCP servers configured in Codian Settings (previously exclusive to Codex).

**Discovery flow:**
1. On each query, enumerate all enabled MCP servers
2. Connect to each server and call `tools/list`
3. Apply the read-only filter
4. Convert MCP tools to OpenAI-compatible function-calling schemas
5. Merge with built-in DeepSeek tools (Skill, Read, Grep, Write, Edit, Undo)
6. Inject into the tool loop

**Execution flow:**
1. LLM calls `mcp__<server>__<tool>` via function calling
2. `executeMcpCall()` parses server/tool names
3. Connects to the MCP server, calls the tool, and disconnects
4. Returns the result to the LLM for natural language summarization

**Read-only filter:**

| Allowed (auto-execute) | Blocked |
|------------------------|---------|
| list, get, read, search, find, query | write, create, delete, remove, destroy |
| fetch, show, view, describe, check, count | update, modify, patch, edit, change |
| export, download, lookup, inspect, browse, scan | execute, exec, run, bash, shell, command |
| | install, uninstall, deploy, publish, push |
| | send, post, put, submit, dispatch |

**Verified MCP servers:**
- Eagle MCP (`mcp__eagle-mcp__item_query`) — verified working

**Configuration:** No additional setup required. MCP servers configured in Codian Settings → MCP Servers are automatically discovered and filtered for DeepSeek.

### DSML Protocol Filtering

DeepSeek models may emit internal DSML (DeepSeek Markup Language) tokens in the text content stream. These are now automatically stripped before rendering:

- `<|DSML| ...>` — DSML block markers
- `<|invoke| ...>` — tool invocation markers
- `<|parameter| ...>` — parameter markers

The filter uses regex `<\|[^|>]+\|[^>]*>` to match and remove complete DSML tokens. A carry-over buffer handles tokens that span streaming delta boundaries.

### MCP Tool Timeout & Error Handling

- Connection timeout: 10 seconds
- Tool call timeout: 30 seconds
- Abort via Esc key (wired to `AbortSignal`)
- Errors show `[Codian MCP]` prefixed diagnostic logs
- Connection failures are non-fatal — fall back to built-in tools

### Architecture
```
DeepSeekRuntime.query()
  → enumerateMcpToolsForDeepSeek(mcpManager)
    → mcpManager.getServers() → filter enabled
    → connect + listTools per server
    → isReadOnlyMcpTool() filter
    → mcpToolToOpenAI() schema mapping
  → allTools = [DEEPSEEK_P1_TOOLS, ...mcpTools]
  → streamAPICall(messages, allTools)
  → LLM calls mcp__server__tool
    → executeMcpCall() → callMcpTool()
      → connect → callTool → disconnect
```

## Known Limitations

1. **MCP write tools are blocked.** Only read-only tools (list, get, search, query, etc.) are available to DeepSeek.
2. **MCP tools are re-discovered on every query.** No persistent connection pooling yet.
3. **No MCP streaming.** Tool results are returned as complete blocks.
4. **No MCP rollback.** MCP tool calls are not tracked in the TransactionLog.

## Compatibility

- **Codex provider**: Unchanged — all existing functionality preserved
- **Codex MCP**: Unchanged — continues to use Codex CLI for full MCP support
- **Obsidian**: v1.8.9+ required (unchanged)

## Upgrade Notes

1. No breaking changes
2. MCP servers already configured in Settings are automatically available to DeepSeek (read-only tools only)
3. Write/Edit/Undo continue to require user confirmation
4. DSML tokens no longer appear in chat UI
