# v1.3.74-deepseek-write-edit

## Overview

This release adds **Write**, **Edit**, and **Undo** tools to the DeepSeek provider, with mandatory user confirmation, vault sandbox protection, and a per-session transaction log. All changes are isolated to the DeepSeek runtime — the Codex provider is unchanged.

## What's New

### Write Tool

Create new files or overwrite existing files in the vault.

- Path must be relative to the vault root
- User confirmation is required before any file modification
- A diff preview (old size → new size, content preview) is shown in the approval dialog
- Parent folders are auto-created if they don't exist
- Recorded in the TransactionLog for Undo support

### Edit Tool

Make targeted string replacements in existing vault files.

- `old_string` must match exactly (character-for-character) in the current file
- If `old_string` is not found, the operation is rejected with a clear error
- Diff preview shows the old and new strings before confirmation
- User confirmation is required
- Recorded in the TransactionLog for Undo support

### Undo Tool

Revert the most recent Write or Edit operation in the current session.

- Shows what will be restored before asking for confirmation
- **For Write (new file)**: moves the created file to trash
- **For Write (overwrite)**: restores the file content before the Write
- **For Edit**: restores the file content before the Edit
- Uses `vault.adapter.write()` for reliable filesystem-level restoration
- Each entry can only be undone once

### User Approval System

Write, Edit, and Undo operations now route through the existing Codian approval callback (`InputController.handleApprovalRequest`).

- **Read-only tools** (Skill, Read, Grep): no confirmation needed
- **Modification tools** (Write, Edit, Undo): user must approve before execution
- User can deny any operation — the tool returns "已被用户拒绝" and the file is unchanged
- Approval decisions are logged

### TransactionLog

A new per-session in-memory journal tracks all Write and Edit operations.

- **Entries**: tool name, file path, action type, pre-action snapshot content, new content, timestamp
- **Storage**: in-memory only (not persisted across plugin restarts)
- **Undo**: reads the most recent non-reverted entry and restores the snapshot
- **Safety**: each entry can only be undone once (`reverted` flag)

### Vault Sandbox

Path validation prevents writes to dangerous locations:

| Blocked | Example |
|---------|---------|
| Outside vault | `/etc/passwd`, `~/Documents/outside.md` |
| `.git/` directories | `.git/config`, `.git/hooks/pre-commit` |
| `node_modules/` | `node_modules/package/index.js` |
| `.obsidian/plugins/` | `.obsidian/plugins/codian/main.js` |
| `.obsidian/themes/` | `.obsidian/themes/custom.css` |
| Hidden directories (except `.claude/`) | `.secret/keys.md` |

## Known Limitations

1. **MCP servers configured in Settings do NOT work with DeepSeek.** MCP capabilities are exclusive to the Codex provider (via Codex CLI). See [MCP Bridge Plan](../plans/v1.3.75-deepseek-mcp.md).

2. TransactionLog is in-memory only — closing Obsidian clears the undo history.

3. Undo only works for the most recent operation. Multi-step undo is not yet supported.

4. No image attachment support for DeepSeek.

## Compatibility

- **Codex provider**: Unchanged — all existing functionality preserved
- **CodexAgentRuntime**: No modifications
- **CodexAppServerClient**: No modifications
- **Obsidian**: v1.8.9+ required (unchanged)
