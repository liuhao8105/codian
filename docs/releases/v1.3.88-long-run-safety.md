# Codian 1.3.88 Long-Run Safety

This release closes the security, liveness, capacity, privacy, installation-hygiene, and maintenance gaps found during the 2026-08-02 six-month stability audit.

## Runtime changes

- DeepSeek `Grep` now searches Markdown through the Obsidian Vault API. Absolute paths, traversal segments, and paths outside the Vault are rejected; no shell is invoked.
- Vault search stops at 10,000 files, 64 MiB of source, 10 seconds, or 200 matches and reports truncation explicitly.
- DeepSeek history is limited to 80,000 characters total and 20,000 per message. The current prompt is rejected above 200,000 characters.
- Tool results are limited to 50,000 characters, serialized API requests to 2 MiB, and SSE/in-progress response components to 1 MiB.
- DeepSeek response headers have a 30-second timeout; an active SSE stream has a 90-second inactivity timeout. Cancellation clears listeners, timers, and reader resources.
- Persistent diagnostics now retain only bounded operational metadata. Notification bodies, tool arguments, file content, absolute paths, environment values, base URLs, and JavaScript stacks are not persisted.
- Codex MCP discovery expires after 60 seconds and explicit reload clears it immediately. The Codex model catalog refreshes when Codian opens after six hours without a successful refresh.

## Long-run maintenance

- Local diagnostics warn when `.codian` reaches 512 MiB or 10,000 files and report only the count of historical plugin backup directories.
- The installed-plugin verifier requires exactly `main.js`, `manifest.json`, `styles.css`, and `data.json`, checks the expected version and runtime SHA-256 values, and rejects backup directories or other extra entries.
- Both affected `brace-expansion` dependency lines are pinned to patched releases: 1.1.17 and 2.1.3.
- CI runs on pull requests, pushes to `main`, manual dispatch, and a weekly schedule. Production and development audits remain separate gates.
- Dependabot checks npm and GitHub Actions weekly, groups minor/patch updates, limits open requests to five, and never auto-merges.

## Compatibility and data boundaries

- Oversized input now receives an explicit rejection or truncation marker rather than allowing unbounded memory growth.
- Invalid regular expressions and out-of-Vault DeepSeek search paths now return explicit errors.
- Existing notes, settings, encrypted secrets, sessions, skills, commands, agents, recovery records, and `data.json` remain preserved.
- Historical `.backup-*` directories are archived outside the Vault after digest verification; they are not deleted.
- No database, server, Docker service, telemetry, paid service, account, or new API key is introduced.

## Verification gates

The release requires successful type checking, linting, full unit/integration tests, production build, release packaging, release checksum verification, production audit, full-development audit, focused fault/capacity tests, installed-layout verification, GitHub CI, remote asset hash comparison, Obsidian restart, and a live Codex response.

Local release verification on 2026-08-02 completed with:

- 144 test suites and 3,942 tests passed;
- 8 focused fault/capacity suites and 65 tests passed in serial mode;
- type checking, linting, production build, five-asset release packaging, and SHA-256 release verification passed;
- production audit: zero vulnerabilities;
- full-development audit: zero vulnerabilities.
