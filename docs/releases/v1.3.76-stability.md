# v1.3.76-stability

## Overview

Production stability release. No new features — focused on cleanup, safety, and user experience polish for the DeepSeek provider. Codex provider is unchanged.

## What's New

### Session-Level Approval Memory

Write, Edit, Undo, and read-only MCP tools now auto-approve after the first confirmation in a session.

| Operation | First Call | Subsequent Calls |
|-----------|------------|------------------|
| Write | User confirms | Auto-approved |
| Edit | User confirms | Auto-approved |
| Undo | User confirms | Auto-approved |
| mcp__* (read-only) | User confirms | Auto-approved |
| Future: Bash/Delete/write-MCP | Always confirm | Always confirm |

Approval memory is cleared on new conversation or session reset.

### TransactionLog Auto-Prune

The per-session action journal now has a 50-entry limit. When exceeded, oldest reverted entries are removed first, then oldest non-reverted entries.

### Debug Log Cleanup

Production-verbose debug logs removed from:
- Per-tool MCP discovery iteration
- Per-server enumeration details
- Individual tool name printing

Kept: summary discovery logs, error/warning logs.

### Safety Fixes

- **activeAbortController guard**: replaced non-null assertion (`!`) with explicit guard and early throw
- **MCP connect race**: fixed double-close race condition between connect timeout and finally block
- **MCP error sanitization**: file paths in error messages replaced with `[path]`

### MCP Read-Only Allowlist Expansion

Added common MCP tool prefixes to the read-only allowlist:
- `item_*`, `tag_*`, `folder_*`, `collection_*`
- `asset_*`, `file_*`, `note_*`, `vault_*`

Fixes Eagle MCP `item_query` and similar tools being incorrectly blocked.

## Known Limitations

- MCP write tools are not yet supported for DeepSeek
- MCP tools re-discovered on every query (no connection pooling)
- Bash, Delete, and high-risk operations not implemented for DeepSeek

## Compatibility

- **Codex provider**: Unchanged
- **Obsidian**: v1.8.9+ required

## Upgrade Notes

1. First Write/Edit/Undo/MCP call in each session still requires confirmation
2. Subsequent calls in the same session are auto-approved
3. New conversation resets the approval memory
4. No breaking changes
