# Codian 1.3.84 Long-Run Completion

## Purpose

This release closes the bounded-growth, restart recovery, local diagnostics, and reproducible-delivery gaps that remained after the verified 1.3.83 stability release. It is intended for continuous desktop use over months without adding a cloud service or operational backend.

## Long-run safeguards

- Diagnostic logs redact credentials, token-like assignments, URL secrets, and home-directory paths before writing.
- Each diagnostic entry is byte-bounded, and only three rotated generations are retained.
- Codex session discovery reuses a deterministic index and stops after 20,000 visited entries per rebuild.
- Local diagnostics scan at most 20,000 vault entries and reports a truncation warning instead of continuing without a bound.
- Recovery snapshots are capped at 1 MiB each, 50 records, and 8 MiB total. Active recovery records are never silently discarded to make room.

## Persistent manual recovery

DeepSeek Write and Edit operations now write a pending recovery record atomically before changing a note. The record is marked applied only after the note change succeeds. Pending or applied records remain available after Obsidian restarts.

Undo still requires explicit user approval. Before restoring, Codian compares the current file with the recorded post-write hash. If the file changed later, recovery stops instead of overwriting newer content. No file is restored or deleted automatically.

Recovery metadata is stored locally at `.claude/recovery-journal.json`. It contains operation metadata and the pre-write snapshot required for recovery, so vault-sync users should treat it as duplicated note content.

## Recovery boundary

Persistent recovery covers only Codian-owned DeepSeek Write/Edit operations. It does not promise universal rollback for:

- Codex App Server file changes, because complete pre-write file contents are not exposed for every action.
- Bash commands, which may perform arbitrary multi-file or external changes.
- MCP tools and other external services, whose actions may occur outside the vault.

The deprecated Codex thread rollback operation does not restore local files. These limitations are documented explicitly; the release does not simulate or claim a rollback that cannot be verified.

## Secret-free local diagnostics

The command `Copy local diagnostics (secret-free)` copies a JSON snapshot to the local clipboard. It contains the plugin version, provider, permission mode, secure-storage status, aggregate `.claude` file count/size, recovery-state counts, and machine-readable warnings.

It excludes API keys, environment values, usernames, absolute paths, file names, file contents, logs, and model submissions. The command performs no telemetry or network request.

## Packaging and rollback

The install archive contains exactly:

- `main.js`
- `manifest.json`
- `styles.css`

The rollback archive contains the same three files from the verified 1.3.83 release. `npm run verify:release` rejects version disagreement, missing/extra/duplicate archive members, damaged ZIPs, source/archive byte differences, an invalid rollback version, or any SHA-256 mismatch.

To package locally, set `CODIAN_ROLLBACK_DIR` to a verified 1.3.83 plugin directory and run:

```sh
npm run build
npm run package:release
npm run verify:release
```

## Dependencies and operating cost

- New runtime dependencies: none.
- New API keys or accounts: none.
- Database, server, or Docker requirement: none.
- Telemetry: none.
- Direct operating cost: none beyond the existing model/provider usage selected by the user.

The production dependency audit reports zero vulnerabilities when checked against the official npm registry. The full development-tree audit still reports the known `brace-expansion` denial-of-service advisory through lint/test tooling. npm's complete automated fix requires a breaking ESLint 10 upgrade, so this release does not force that unrelated toolchain migration. These packages are not bundled into the installed Obsidian runtime.

Obsidian minimum version remains `1.4.5`.
