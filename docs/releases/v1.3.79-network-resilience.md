# v1.3.79-network-resilience

## Overview

This release improves how Codian handles a final Codex-to-ChatGPT transport failure after the Codex CLI has exhausted its built-in retries.

## What Changed

- Retryable Codex App Server errors continue to be ignored while the CLI reconnects.
- Final `backend-api/codex/responses` stream disconnects are converted into a concise Chinese recovery message.
- Raw backend endpoint URLs are no longer exposed in the chat for this known connection failure.
- Unrelated App Server errors keep their original message for diagnosis.

## User-Facing Message

> Codex 与 ChatGPT 的连接已中断，自动重试后仍未恢复。请检查网络或代理设置，然后重新发送消息。

## Root Cause Boundary

Codian does not implement or replace the Codex CLI transport. WebSocket reconnection and HTTPS fallback remain owned by the Codex CLI. This release improves the final failure experience without weakening TLS, changing proxy settings, or adding a second retry loop.

## Technical Details

- Updated `CodexAgentRuntime` final error formatting.
- Added a regression test using the App Server error shape observed in the runtime diagnostic log.
- Preserved the existing behavior for retryable and generic final errors.

## Compatibility

- Codex CLI: `0.144.5` verified locally.
- Obsidian minimum version: unchanged (`1.4.5`).
- No dependency changes.
- No database, API key, server, or Docker requirements.

## Known Limitation

The plugin cannot prevent an external network, proxy, TLS, or ChatGPT service interruption. After connectivity is restored, resend the message.
