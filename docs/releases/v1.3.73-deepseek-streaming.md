# v1.3.73-deepseek-streaming

## Overview

This release adds **DeepSeek SSE streaming** with a **multi-turn tool loop** (Skill / Read / Grep) and natural paragraph-by-paragraph text output. The Codex provider is unchanged.

## What's New

### DeepSeek SSE Streaming

DeepSeek chat responses now stream incrementally via Server-Sent Events (SSE) instead of returning as a single buffered response. Text appears paragraph-by-paragraph with natural sentence-aware pacing.

- **SSE parser**: Reads `response.body` as a ReadableStream, parses `data:` lines, handles `[DONE]` marker
- **Chunk buffering**: Text is aggregated into 80-character buffers before rendering
- **Sentence flush**: Immediate flush on sentence-ending punctuation (`。！？\n`)
- **Interval throttle**: Maximum 150ms between flushes for responsiveness
- **Final flush**: Remaining buffer is flushed on stream completion — no text loss

### DeepSeek Tool Loop (P1)

DeepSeek now supports a multi-turn tool-calling loop with three read-only tools:

| Tool | Description |
|------|-------------|
| **Skill** | Loads skill instructions from `.claude/skills/` into conversation context |
| **Read** | Reads files from the Obsidian vault via `app.vault.cachedRead()` |
| **Grep** | Searches for patterns in vault Markdown files via `grep` child process |

**Tool loop protections:**

- **Max rounds**: 10 tool-calling rounds per user message (safety net)
- **Duplicate detection**: Repeated Read (same file) or Grep (same pattern) calls are counted; 3+ duplicates force a stop
- **No-progress detection**: Consecutive rounds with identical tool results force a stop after 3 rounds
- **Early warning**: After 6 rounds, the model is required to summarize and answer
- **Forced summary**: A system instruction is injected, and a final API call without tools is made

### Reasoning Content Preservation

DeepSeek reasoning models (`deepseek-reasoner`) require `reasoning_content` to be passed back on subsequent turns in a multi-turn conversation. The tool loop now:

- Accumulates `delta.reasoning_content` from streaming chunks
- Injects it into the assistant message when tool calls are made
- Preserves it across all rounds of the tool loop

This eliminates the HTTP 400 error: _"The reasoning_content in the thinking mode must be passed back to the API."_

### Streaming UX Tuning

| Parameter | Value | Purpose |
|-----------|-------|---------|
| `FLUSH_SIZE` | 80 chars | Minimum buffer before flush |
| `FLUSH_INTERVAL` | 150ms | Maximum time between flushes |
| Sentence end | `。！？\n` | Flush immediately |
| Clause end | `，；：,;:` | Flush if buffer ≥ 40 chars |

### Bug Fixes

- Fixed scroll-to-bottom race condition where `hideThinkingIndicator()` DOM removal triggered a scroll event that incorrectly set `autoScrollEnabled = false`, blocking the final scroll at stream completion
- Fixed DeepSeek `reasoning_content` not being preserved across tool loop rounds

## Known Limitations

| Limitation | Detail |
|------------|--------|
| **No image support** | DeepSeek provider does not support image attachments |
| **Read-only tools** | Only Skill / Read / Grep — no Bash, Write, Delete, or high-risk MCP actions |
| **No subagents** | DeepSeek does not support Agent/Task subagent spawning |
| **No rewind/fork** | Rewind and fork are not available with DeepSeek |
| **No session resume** | DeepSeek sessions cannot be resumed across plugin restarts |
| **Non-streaming tool results** | Tool execution results are displayed as complete blocks, not streamed |

## Compatibility

- **Codex provider**: Unchanged — all existing functionality preserved
- **CodexAgentRuntime**: No modifications
- **CodexAppServerClient**: No modifications
- **StreamController**: No modifications (already supports all StreamChunk types)
- **Obsidian**: v1.8.9+ required (unchanged)
