# Codian 1.3.90 DeepSeek Latency

This release removes avoidable DeepSeek startup latency caused by unconditional external MCP discovery.

## Root cause

- DeepSeek enumerated every enabled MCP server before emitting the runtime user event or starting the API request.
- A failing local MCP server could therefore delay an unrelated ordinary chat turn until its connection attempt ended.
- Live diagnostics measured 18.419 seconds in MCP discovery and 250 milliseconds from the DeepSeek API request to response headers on the same turn.

## Runtime changes

- Ordinary DeepSeek chat skips external MCP discovery and proceeds directly to the streaming API request.
- An explicit `@server-name` mention or MCP selector choice discovers only the requested servers.
- DeepSeek's built-in vault tools remain available on every turn.
- Existing MCP settings are not changed, disabled, or deleted.

## Compatibility and boundaries

- Codex runtime behavior is unchanged.
- DeepSeek model, API endpoint, encrypted API key, conversation history, notes, sessions, recovery data, and user settings are preserved.
- No dependency, API key, database, server, Docker service, telemetry, paid service, account, plugin, Skill, or MCP server is introduced.
- Obsidian minimum version remains `1.4.5`.

## Verification gates

The release requires type checking, linting, all unit and integration tests, production build, production and full dependency audits, exact package verification, installed-layout verification, Obsidian restart, and live DeepSeek and Codex short-chat timing checks.
