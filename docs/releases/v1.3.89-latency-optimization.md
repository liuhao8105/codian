# Codian 1.3.89 Latency Optimization

This release reduces avoidable Codex turn latency without changing conversation data semantics or silently switching models.

## Runtime changes

- The selected thinking level is now sent through the Codex App Server `turn/start.effort` field. `off` leaves the App Server default untouched.
- Stable Codian rules are sent through `developerInstructions` when starting or resuming a thread, instead of being copied into every user message.
- Runtime diagnostics record only the requested effort and instruction character count; instruction content is never written to diagnostics.
- Codex App Server now starts with the Obsidian vault as its process working directory instead of the Codex CLI installation directory. This removes unrelated `/opt/homebrew/.codex` discovery without trusting or modifying it.
- The fixed prompt retains Codian identity, Obsidian formatting, vault/export/external path boundaries, context tags, local-only vault search, current web verification rules, wikilinks, image handling, strong rules, and custom instructions.
- Generic tool, subagent, task-list, and Skill manuals already supplied by Codex were removed from the fixed prompt.

## Compatibility and boundaries

- No automatic model switching, history deletion, conversation summarization, current-note detachment, or MCP enablement was added.
- Existing notes, settings, encrypted secrets, sessions, conversations, skills, commands, agents, recovery records, and `data.json` remain unchanged.
- No dependency, API key, database, server, Docker service, telemetry, paid service, account, plugin, Skill, or MCP server is introduced.
- Obsidian minimum version remains `1.4.5`.

## Verification gates

The release requires fresh type checking, linting, all unit/integration tests, production build, exact release packaging, SHA-256 release verification, separate production and development dependency audits, installed-layout verification, Obsidian restart, and a live short-chat timing check.
