# v1.3.82-mcp-on-demand

## Overview

This release prevents ordinary Codian chat from being blocked by unrelated global Codex MCP servers. MCP servers are started only when explicitly requested for the current turn, and stalled startup no longer waits forever.

## On-demand MCP

- Discovers enabled, directly configured global MCP section names from the local Codex configuration.
- Keeps only sanitized names in memory and discards all transport configuration and credentials.
- Disables directly configured global MCP servers for ordinary chat without overriding MCP services injected by Codex plugins.
- Enables a server for the current turn when the prompt explicitly contains `@server-name`.
- Falls back to the existing Codex behavior if safe MCP discovery is unavailable.

## Stall Recovery

- Watches for MCP startup that remains incomplete before any model or tool activity.
- Rebuilds the App Server once, disabling the stalled configured MCP for the retry.
- Watches for a turn that produces no model or tool activity.
- Returns a concise Chinese recovery message after the single rebuild is exhausted instead of displaying an endless running state.
- Never retries after model or tool activity begins, avoiding duplicate external actions.

## Compatibility

- Includes the model synchronization, network handling, and cross-model session safety from v1.3.81.
- Codex CLI: `0.144.5` verified locally.
- Obsidian minimum version: `1.4.5`.
- No new dependencies, API keys, databases, servers, or Docker services.
